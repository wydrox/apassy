# Secret context held-out v1

Independent synthetic evaluation input for the unused A/B context candidate. This
artifact changes no route, schema, access right, runtime policy or provider call.
Labels follow supervision section 4 and integration clarification R1: a missing
declaration keeps environment/scope unknown and sources none. A clean established
read serving the task can be `allow_ok` if no other must-ask condition or local rule
applies. This is an experimental label, not an authorization to execute.

## Reproduction and integrity

From the integration checkout:

```sh
python3 tests/evals/secret_context_heldout_v1.py --write
~/.local/bin/heavy-check python3 tests/evals/secret_context_heldout_v1.py --check
```

Generation uses only Python stdlib, fixed iteration order and canonical sorted ASCII
JSON with one newline per row. No seed, clock, network, owner data, secret values,
canaries, tokenizers or model weights are used. The manifest pins exact JSONL bytes
and generator bytes by SHA-256, label/class counts, relationship counts and the
rubric version/text. Hashes identify public synthetic artifacts, never credentials.
The checker compares regenerated bytes and validates schema, vocabulary, labels,
minimum populations, unique IDs and reference consistency. Preserve JSONL bytes
when transferring: whitespace or newline edits invalidate the manifest.

| Population | Rows |
| --- | ---: |
| Total | 1060 |
| Model-scored allow_ok | 420 |
| Model-scored must_ask | 510 |
| Deterministic ask | 130 |
| Counterfactual pairs | 360 |
| Injection variants (included above) | 120 |

Each mandatory class (`cold_start_no_declaration`, `known_with_owner_history`,
`changed_or_rotated`, `repeat`, `multi_secret`) has 60 base allow rows plus 10
injection allow variants, and the same number of risky rows. Production read-only
has the same population. Additional writes, deletes and task-mismatched reads are
risky. Short actionable commands keep budget measurements useful; three-secret
rows still measure the real coverage penalty and must not be shortened at scoring.
Local-rule rows carry the shared matrix row ID; they are excluded from model
accuracy populations and always ask. Their row ID represents the synthetic local
check result, including checks whose full inputs are outside the context schema.

Pairs share request, command, purpose, action and family; only credential facts
and the corresponding label/rationale change. Pair references point from the
must-ask member to the allow member. Injection variants reference their base row,
keep its facts and label, and append untrusted claims only to request/purpose.
They have no pair reference, avoiding double-counting the base counterfactuals.
Denial examples have no later allow; conflict examples remain risky irrespective
of chronology. Bucketed counts cannot reconstruct a later owner approval.

## Independence and limitations

This author did not read W4 generators, trainer/evaluator templates or uncommitted
content. Only the shared supervision contract/rubric and R1 clarification informed
the data. Families are `H1:*`, disjoint by namespace from training `G1:*`.
Independence is procedural within a shared checkout, not statistical or cryptographic
isolation. The evaluator must still reject actual family and (user_request, command)
overlap. Freeze checkpoint, threshold, configuration and contract before a fresh
evaluator opens held-out data. Do not tune against this file or send it to W4.

The set uses synthetic task/resource variation and does not estimate real user
preferences or production traffic. Injection variants and pairs are correlated;
report base populations separately as well as the full synthetic N. No zero-error
claim here establishes a production confidence bound. Context fit, tokenizer
measurement, latency, RSS, head training and the B PASS/FAIL/UNSUPPORTED report
belong to the parent evaluation. Artifact integrity alone is not B PASS.

## Vault evidence limits and integration

`src/vault/decision_evidence.rs` reads a deferred transaction snapshot of metadata
only. It never selects item field values, calls details/reveal/detect, or writes
history/revisions. SQL reads item kind, stored declaration/provider, explicit source
row presence, origin existence, scoped use metadata and event kind/detail. Event
details are parsed using current `EditChange::parse_detail`; title edits are not
secret edits. Raw event detail never enters the returned evidence or model text.

The window is inclusive at its start and ends at query `now`; future rows cannot
establish owner decisions, agent prior use or event ages. Subtraction saturates;
counters use checked increments and overflow becomes Unknown. Query host coverage
means each query host occurs in the retained row, including when that row has
additional hosts. Other agent/project/action or missing query-host coverage makes
a denial other-scope. Empty project or missing agent never matches the same scope.

Global use-log truncation makes all owner counters unknown when the cap is reached
and its oldest row lies after the window start. Event truncation makes both change
ages unknown at the item cap with no retained created/tracked beginning and oldest
event inside the window. A beginning before a future query timestamp is required;
future created/tracked events cannot establish coverage. Absence records only local
retained history, never cross-device certainty. Agent-used means a retained allowed
decision, not successful execution by any provider.

Owner-set and legacy declarations both lack a source row: this API returns None,
never the old API's default Owner. No detector or signal fabrication repairs a
missing declaration. Evidence contains no item revision; it is a consistent read
at call time, not a durable snapshot or authorization promise. Later item, history
or scope changes require a fresh read and existing execution revision checks.

The parent owns module exports and `tests/it.rs` registration. Private unit tests
cover raw SQL cap, time, provenance, scope and read-only boundaries; the assigned
integration file covers the public API. Rust compilation/tests were NOT RUN here
because local Rust builds are prohibited; CI must validate the integrated revision.
No model evaluation or provider execution was performed.
