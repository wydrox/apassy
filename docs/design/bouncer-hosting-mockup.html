Where the bouncer brain runs

This Mac: nothing leaves this Mac.

My Server: your server answers over https with a token. Free.

Apassy Connect: Apassy runs it for you. Comes with Connect.

The bouncer gate on this Mac decides every run. No answer means Apassy asks you.

  • Row: label “Runs on”, a menu with the current choice, ⓘ beside it. The default is This Mac (no vault row).
  • ⓘ holds the help: the three choices in one line each, and the rule that the gate decides on this Mac.
  • No empty pane: the row needs no note while the brain runs on this Mac.

3c · Consent (version 1)

What Leaves This Mac

Each bouncer request goes to brain.tail0a1b.ts.net.

Sent
  • The user request and the purpose
  • The shell command, with paths in your project and home folder shortened
  • The bouncer heads trained on your decisions (numbers, no text)
Never sent
  • Secret values
  • The vault and the full paths of your project and home folder
A server that someone else controls can make the bouncer run development and staging commands without asking you. It can never allow production, a hard check, secret output or another host.
Each change needs Touch ID.

3d · The owner check (fresh, every time)

Change the bouncer brain host

Use the bouncer brain on your server at https://brain.tail0a1b.ts.net. Each bouncer request goes there: the user request, the purpose, and the shell command, with paths in your project and home folder shortened. The bouncer heads trained on your decisions go there too: numbers, no text. No secret value, the vault, or a full path of your project or home folder leaves this Mac, and the bouncer gate still decides on this Mac. A server that someone else controls can make the bouncer run development and staging commands without asking you. It can never allow production, a hard check, secret output or another host.

Touch ID or the passphrase. The “How often to ask” window never covers this.

CancelUse Passphrase…
  • Address: https:// with a host name (valid_host_url). ⓘ: “Use a public certificate, for example Tailscale Serve: tailscale serve --bg 8770. A private certificate does not work.” A wrong address shows “Use https:// and a host name.” under the field, and Continue stays disabled.
  • Token: generated when the sheet opens (generate_bearer, 32 random bytes). The token shows as dots; Show reveals it; Copy copies the token through the concealed clipboard, cleared after 30 s. Under it, the start commands (docker_run_lines) hold no token: a token file that the owner fills by pasting into cat, read by the container through LAYA_API_KEY_FILE, and the port on loopback (-p 127.0.0.1:8770:8770) for Tailscale Serve. Copy Commands copies them as plain text. Paste a Token switches to a masked field (16 to 512 characters, valid_bearer).
  • Consent: the words of version 1 (HOSTING_CONSENT_VERSION); the change carries the version, and the owner check names it. A new version of these words shows the sheet again at the next change.
  • One blue button per step: Continue, then Use My Server (with the Touch ID glyph). Back keeps the address and the token.
  • Owner check: OwnerRequest::ChangeBouncerHosting. The global Touch ID window never covers it. The sheet closes only after a passed check; a cancel keeps it open with the same token.
