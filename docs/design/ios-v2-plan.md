# The iPhone app v2: implementation plan

Date: 2026-10-12. Source: [ADR 0026 §8](../adr/0026-simple-app.md) and the approved mockup [ios-v1-mockup.html](ios-v1-mockup.html). Branch: `feat/low-friction-access` (draft PR #15). No release, no TestFlight, no real vault: synthetic data only.

## What changes

| Now | v2 |
| --- | --- |
| Tabs: Home, Items, Watchtower, Approvals, Search | Tabs: **Vault**, **Decisions**, **Agents**, Search (iOS 26 tab bar, search role) |
| Home with kinds and favorites; Items A to Z | Vault: Watchtower card, "All credentials", folders (nested), Shared. A folder lists its credentials with provider tiles and a red dot for production |
| "+" opens a form for each kind | "+" opens **New Credential**: paste (or scan a QR code), then Add. Detection runs in the core on the iPhone. The full editor stays ("Pełen zakres") |
| Item detail: fields | Credential: secret, variable, folder, agent use, rules from the owner's answers, options ("Always ask me", environment) |
| Approvals: a picker between relay questions and the companion | Decisions: Waiting (with a timer), Requests, Suggestions; detail with a fixed glass bottom bar: Allow ACTION in PROJECT · Deny · Allow Once. Allowing asks for Face ID; stricter answers do not |
| Settings: one long sheet | Settings: General, Devices, Security, Advanced, like the Mac window |

Agents, agent use, rules, requests, and suggestions live in the Mac's vault (they do not sync). Until the Mac→iPhone feed exists ([stage5-plan.md](stage5-plan.md), "The Mac feed"), these places show **"Available when the Mac is connected"** and nothing else. They never show invented data.

## Streams

Each stream works in its own worktree on its own branch from `feat/low-friction-access` and touches only its files. `ApassyCompanion.xcodeproj/project.pbxproj` is generated by XcodeGen: a stream that adds files runs `xcodegen generate --spec project.yml` and commits the result; the integrator regenerates it after each merge.

| Stream | Owns | Wave |
| --- | --- | --- |
| **F: data** | `ios/ApassyCore/**`, `ios/ApassyVaultKit/**`, `docs/contracts/ios-core-v1.md` | 1 |
| **B: shell and settings** | `Views/Vault/VaultTabView.swift` (the `TabView` only), `VaultTab` in `Views/Vault/VaultComponents.swift`, `Views/Vault/SettingsView.swift` (may split into `Views/Settings/*`), new `Views/Agents/*` | 1 |
| **D: decisions** | `Views/Main/*` (questions and the companion), new `Views/Decisions/*`, `Models/QuestionsModel.swift`, its model tests | 1 |
| **C1: vault browse** | new `Views/Vault/VaultRootView.swift`, `FolderView.swift`, `ItemDetailView.swift`, `Vault/ItemDetailModel.swift`, `Vault/VaultModel.swift`, provider tiles | 2 (after F) |
| **C2: adding and editing** | new `Views/Vault/NewCredentialView.swift`, new `Vault/NewCredentialModel.swift`, `ItemEditorView.swift`, `Vault/ItemEditorModel.swift` (folder picker) | 2 (after F) |

Fixed seams between streams:

- B keeps calling `ApprovalsHub(questions:companion:onSettings:source:)` for the Decisions tab; D rewrites what `ApprovalsHub` shows and keeps that initializer.
- B keeps `HomeView()` as the content of the Vault tab; C1 replaces that one line with `VaultRootView()`.
- New app model files in `Sources/Vault` or `Sources/Models` get a symlink in `ModelTests/Sources/AppModels`.

## The data API (stream F)

Core calls (JSON, contract `ios-core-v1`, additive; an older core answers `unsupported`):

| Call | Request | Answer |
| --- | --- | --- |
| `folders` | – | `{folders:[{uuid, parent, name, position, count}]}`; `count`: items directly in the folder, not archived |
| `folder_create` | `{parent?, name}` | the folder |
| `folder_rename` | `{uuid, name}` | `{}` |
| `folder_move` | `{uuid, parent?}` | `{}` |
| `folder_delete` | `{uuid}` | `{moved}`: credentials moved to the parent |
| `item_folder_set` | `{id, folder?}` | `{}` |
| `detect` | `{text}` | `{found:[{index, title, kind, provider, env_name, hosts, environment, risk, line, summary, fields:[{name, label, secret, preview}]}]}`. A secret field's `preview` is masked; no secret value leaves the core |
| `add_pasted` | `{text, folder?, pick?}` | `{items:[{id, revision, title}]}`. The core detects `text` again and saves the picked entries (all when `pick` is absent) in one transaction, origin "pasted on iPhone" |
| `item_options_set` | `{id, always_ask?, environment?}` | `{}`; the environment is saved with the owner as its source |

`Row` gains `folder`, `provider`, `production`. `Detail` gains `folder`, `folder_path`, `provider`, `env_name`, `always_ask`, `environment`, `environment_source`. All new fields are optional in Swift, so an older core still decodes.

Swift: the new `VaultService` requirements have default implementations that throw the existing "unsupported" error (as the passkey calls do), so the app streams compile before the core lands. Models in `ApassyVaultKit/Organize.swift`; `PreviewVaultService+Organize.swift` with synthetic folders ("Acme" › "Billing", "Personal"), providers (Stripe, GitHub, Postgres) and one production credential; `CoreVaultService+Organize.swift` over the core.

Shared vaults (ADR 0026 §6) are not built yet (V3). The Vault root shows a "Shared" section only when the core reports shared vaults; until then it shows nothing there.
