## Current findings, ranked P0–P3

**11 findings: P0 0, P1 5, P2 5, P3 1.** P1 means substantial security or credential-use failure; P2 means bounded availability, recovery, or completeness risk; P3 means misleading documentation. These priorities differ from the old UX audit's definition of P0. No P0 compromise was demonstrated. Examples are synthetic reasoning cases, not executed reproductions.

### A01 — P1: Desktop vault has no automatic inactivity/session-lock boundary

- **Evidence:** `src/desktop/mod.rs:480` continues polling when hidden/minimized; `src/desktop/mod.rs:464` locks at exit; `src/desktop/owner_check.rs:2511` implements explicit lock; `src/desktop/ui/settings_view.rs:24` describes Security as Touch ID/passphrase. Searches across `src` and `native` found no vault idle timer, workspace sleep/session-lock observer, or auto-lock preference. The 30-minute timer in `src/desktop/owner_cli.rs:285` expires a CLI session, not the vault.
- **Impact:** leaving Apassy open leaves its decryption session and agent access available indefinitely, including after an idle interval. A screen-lock cycle does not itself invoke vault lock in this implementation. OS login security still applies; this is absence of an app-level boundary, not proof of an OS bypass.
- **Fix sketch:** configurable idle lock plus sleep/session-lock notification handling; funnel through existing lock path to clear drafts/reveals, invalidate approvals and stop companion work. Define ongoing-run behavior explicitly.

### A02 — P1: Short plaintext secrets bypass output redaction

- **Evidence:** `src/broker/exec.rs:28` sets `MIN_MASK_BYTES = 4`; `src/broker/exec.rs:342` excludes shorter values from masking. `src/broker/exec.rs:104` returns masked stdout/stderr to callers. Existing test `mask_prefers_longer_values_and_skips_short_ones` codifies this behavior.
- **Impact:** a legitimately stored 1–3-byte password/PIN delivered in real-value mode can return verbatim in agent tool output, with no encoding needed. This is a deliberate current limitation, but stronger than README's blanket never-receives-value promise. Encoded-output escape is separately documented and not counted as a new finding.
- **Fix sketch:** refuse short values for real-value execution unless an explicit owner-visible limitation is accepted, or suppress output for that run; do not silently skip masking while promising concealment.

### A03 — P1: CLI CSV migration discards Website metadata

- **Evidence:** `src/cli/import.rs:252` reads URL; `src/cli/import.rs:305` retains only derived service; construction through `src/cli/import.rs:365` never adds Website. `src/owner/wire.rs:105` has no dedicated website input (custom details remain available). This covers Bitwarden and 1Password CSV through the CLI; the separate desktop importer has its own mapping.
- **Impact:** import can succeed with the password stored while its site eligibility and safe domain search are missing. The original complete URL, including path/multiple URIs, cannot be recovered from a derived service name. This is an import-fidelity finding, without reviewing extension implementation.
- **Fix sketch:** preserve website(s) using the canonical owner input/core URL representation; add import readback cases for scheme, port, path and several URIs.

### A04 — P1: CLI CSV import changes valid password bytes

- **Evidence:** `src/cli/import.rs:275` extracts the password without trimming, but `src/cli/import.rs:308` then removes every trailing CR/LF. RFC 4180 quoted fields can legitimately contain those bytes (`src/cli/import.rs:195`).
- **Impact:** a password ending in a line break is imported as a different password and later fails authentication. Record delimiters are already handled by the CSV reader, so trimming field contents is unnecessary.
- **Fix sketch:** preserve the exact parsed password; normalize only documented metadata. Cover quoted trailing LF/CRLF with byte-for-byte readback.

### A05 — P1: Desktop agent onboarding gives an unsandboxed launch command

- **Evidence:** `src/desktop/ui/agent_onboarding.rs:301` returns plain `claude` (with timeout) or `codex`; `src/desktop/ui/agent_onboarding.rs:322` says restart the host, and `:335` displays that plain Claude launch. Setup writes MCP/hook configuration; it does not wrap the parent host. By contrast `src/cli/setup.rs:42` explicitly instructs `apassy-sandbox` for both hosts; `sandbox/apassy-agent-host.sb:1` only applies when launched through that profile.
- **Impact:** following the graphical success handoff provides working tools without the advertised agent-host filesystem isolation. A configured MCP server and hook do not place an already running agent inside Seatbelt.
- **Fix sketch:** display/copy the sandbox launcher for each host, identify whether the parent is actually isolated, and describe configuration saved separately from connection/first-use verification. Preserve explicit platform limits.

### A06 — P2: MCP enforces the frame limit after unbounded allocation

- **Evidence:** `src/agent/mcp.rs:75` uses unrestricted `read_line`; only `src/agent/mcp.rs:82` checks `MAX_LINE_BYTES`. `line.clear()` retains the allocated capacity for subsequent requests.
- **Impact:** a malformed/oversized host message or a stream without newline can consume memory indefinitely and kill/hang the MCP adapter. This is local adapter availability, not a proven remote unauthenticated broker exploit.
- **Fix sketch:** bounded framing before allocating beyond 64 KiB; drain/reject oversized frames or terminate cleanly. Exercise a missing-newline oversized stream with bounded memory.

### A07 — P2: Long-offline sync copies can resurrect deleted credentials

- **Evidence:** `src/vault/merge.rs:252` retains tombstones for 180 days; `src/vault/merge.rs:2008` deletes older tombstones by wall clock without device acknowledgement. `src/vault/merge.rs:1886` inserts a remote-only item when no surviving local tombstone proves deletion.
- **Impact:** a Mac/file snapshot offline beyond the retention window can reintroduce an item the owner removed. This is a deterministic retention tradeoff in the source, not evidence that resurrection occurred in the owner's vault. Restoring an old backup can reach the same condition.
- **Fix sketch:** retain deletion knowledge until all supported replicas acknowledge it, or require explicit reseeding/review for snapshots older than the deletion horizon. Document the offline-device boundary.

### A08 — P2: Desktop import labels different accounts as already imported

- **Evidence:** `src/import/mod.rs:278` defines duplicate identity as case-insensitive title plus kind; `:291` sets the duplicate flag; `src/desktop/ui/import.rs:400` labels it “Already in the vault”. No username, website, source item ID or credential identity comparison participates. Existing-item scan is `src/desktop/ui/import.rs:185`.
- **Impact:** importing a second account with the same service/title as a stored login can incorrectly suggest it is already present and leave it unselected. Owner can review/override; this is misleading migration selection rather than automatic deletion.
- **Fix sketch:** distinguish “same name” from an identity duplicate; include safe account/site identity and stable source IDs. Offer deliberate conflict resolution and accurate counts.

### A09 — P2: Share is a dead-end UI, not a working team-sharing operation

- **Evidence:** `src/desktop/ui.rs:485` identifies Share as a stub; `src/desktop/ui/items.rs:1081` opens a sheet whose only action is Done and whose text unconditionally says this Mac has no shared vault. `src/desktop/ui/items.rs:943` directs the owner to use Share to populate a shared vault.
- **Impact:** the interface sends an owner trying to share with teammates into a circular path with no team/destination selection or mutation. Relay synchronization of a complete vault is a separate capability and does not close this path.
- **Fix sketch:** implement destination/team management and transactional shared-item membership with readback, or remove the active-looking Share affordance and explain the supported whole-vault workflow.

### A10 — P2: CLI CSV parser accepts malformed quoting as successful input

- **Evidence:** `src/cli/import.rs:178` returns records without an error channel; `src/cli/import.rs:228` emits the final record even when `quoted` is still true. Text after a closing quote also falls through into the field. The other CSV parser explicitly rejects malformed quotes in `src/import/csv.rs:26`.
- **Impact:** a truncated/damaged export can merge later text into a credential field, yet import reports records rather than a parse failure. This amplifies migration data-loss/recovery risk.
- **Fix sketch:** reuse the strict erasing CSV parser; reject unmatched quotes and text after quotes before any import mutation; preserve source row diagnostics without values.

### A11 — P3: README contradicts shipped source and sends owners into unnecessary setup

- **Evidence:** `README.md:161` says 0.3.6; `README.md:167` says passphrase is the only unlock despite `src/desktop/unlock.rs:156`; `README.md:132` says hook requires a source build despite bundled-tool discovery in `src/desktop/ui/agent_setup.rs:187` and current CLI help `src/cli/setup.rs:34`. `README.md:84` still introduces signed downloads as future publication. Release manifests/source are 0.5.7.
- **Impact:** owner may rebuild/install unnecessarily, miss supported unlock/hook setup, or misunderstand which installed version should update. This report does not independently verify public artifact publication.
- **Fix sketch:** regenerate current version/status from release metadata; document actual GUI/CLI setup and reserve historical gates for dated ADRs.
