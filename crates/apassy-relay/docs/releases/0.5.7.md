# Coordinated 0.5.7 release

The relay, Linux CLI, Darwin CLI download, and edge Worker move to `0.5.7`
with the application release. The application changes are iPhone-only (the
History "off" state and the notification status text). The relay and CLI
change only their version and three TLS dependencies in `Cargo.lock`:
`rustls-webpki` 0.103.16 (RUSTSEC-2026-0382), `webpki-root-certs` 1.0.10
(RUSTSEC-2026-0383), and `webpki-roots` 1.0.10 (RUSTSEC-2026-0381). These
remove trust in distrusted intermediates. The core dependency stays at
`73f3399`, and schemas, protocols, bindings, secrets, and limits stay
unchanged. Follow the coordinated release procedure in `../OPERATIONS.md`,
using `0.5.7` and the exact merged relay commit throughout.

## Build and artifact gate

After the release commit is merged, tag that exact commit:

```sh
git tag image-release-0.5.7 <full-merged-relay-SHA>
git push origin image-release-0.5.7
```

Wait for both CI and Image to pass on that SHA. Download all three artifacts
from the same Image run: `relay-image`, `apassy-team-linux-x86_64`, and
`apassy-team-darwin-arm64`. Verify their metadata, checksums, source SHA, and
version. The Linux artifact must retain the workflow's GLIBC 2.31 ceiling.
Verify the image ID, amd64 architecture, and OCI version/revision labels.
Build only through GitHub CI; do not build on the production VPS or a local VM.

## Publish and verify

1. Stage both verified CLI binaries in `deploy/worker/public/dl/`, which is
   ignored and absent in a fresh checkout. Generate combined `SHA256SUMS` and
   `release.json` with version, source SHA, filenames, checksums, and sizes.
2. Run Worker tests and typecheck, then deploy the Worker with its current
   bindings and secrets. Read back its deployment ID; fetch both public
   downloads, metadata, checksums, installer, and guide. Verify downloaded
   bytes against the CI artifacts.
3. Record the running relay image ID and compose image. Create the operational
   backup from OPERATIONS section 13 and retain its folder name. Copy/load the
   verified CI image on `ottervibe`, without any build there. Change only the
   relay image in `/opt/apassy/compose.yaml` to
   `apassy-relay:release-0.5.7`, then run `docker compose up -d --wait` from
   `/opt/apassy`. A restart ends existing relay sessions.
4. Verify the running image ID and OCI revision against CI metadata, container
   health, and `apassy-relay --version`. Public `/healthz` must return HTTP 200
   and `ok`, with `x-apassy-relay-version: 0.5.7` and
   `x-apassy-relay-commit` equal to the exact merged relay SHA.

The previous image is a rollback target only after recording its identity.
This release introduces no schema migration. Do not restore a data backup
for a version-only image rollback.

Verify the macOS app, processed TestFlight build and intended group, Chrome
Web Store publication, and website separately. This relay publication alone
does not complete the coordinated six-component release.
