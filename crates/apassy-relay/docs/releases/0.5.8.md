# Relay 0.5.8 release

This release publishes the relay audit fixes from PR #5: transactional device
and team authentication, consistent backups with snapshot validation, bounded
request deadlines, the hardened vendored tiny_http transport, and atomic
`run_interrupted` termination of pending runs after a restart. The CI advisory
gate and GitHub-artifact-only operations runbook are included.

The relay package, edge Worker, and both downloadable CLIs use `0.5.8`.
The pinned `apassy` dependency remains `73f3399`. Team schema 6 and directory
schema 1003 remain unchanged. This relay deployment does not establish the
publication state of the other Apassy application surfaces.

## Build and deployment gates

Follow the current release runbook in `../OPERATIONS.md`. After green CI,
including dependency advisories, and the approved merge, tag the exact merge
commit `image-release-0.5.8`. Obtain the image and both portable CLIs from the
same successful GitHub Image run. Verify all checksums, release metadata,
architecture, image ID, and OCI version/revision labels against that commit.
Never build on the production VPS or run a local Docker VM.

Stage both verified CLI downloads, combined `SHA256SUMS`, and `release.json`.
Pass Worker tests, typecheck, and asset preflight; deploy the Worker and verify
both public downloads and metadata. On the VPS, preserve the running 0.5.7
image and compose settings, load the verified candidate, take a consistent
backup, and run the isolated restore drill with the candidate immutable image
and its `snapshot-check` before restarting the live relay. Select
`apassy-relay:sha-<full merge SHA>` in production compose and restart only relay.

Require HTTP 200 `ok` with version `0.5.8` and the exact source commit,
authenticated connect/operator smoke checks with test-team cleanup,
`rollback-check` exit 0, successful restore validation, and healthy backup timers.

## Rollback

Stop at the first failed check. If rollout has started, stop relay, restore
`/opt/apassy/compose.yaml.pre-release-0.5.8`, and start only relay with the
retained `apassy-relay:release-0.5.7` image. Verify health and the 0.5.7 source
headers. No schema downgrade or data restore is needed for this patch rollback.
Sections 19-21 describe historical migrations; do not copy `.pre-v6` databases.
A full backup restore is reserved for separately reviewed data recovery.

If the Worker was changed, from `deploy/worker` run
`npx wrangler rollback 7b5c0cbb-59a9-4a24-b1bf-1570bc37278f` and verify public
health and matching downloads. Retain the old image, compose backup, fresh
backup, artifact identity, and deployment evidence for the owner.
