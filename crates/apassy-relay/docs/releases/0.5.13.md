# Relay 0.5.13 publication procedure

Prepared 2026-11-02. These commands are a procedure for a separately authorized
operator; preparation does not authorize execution. No deployment, image tag,
Worker command, build or test was executed during preparation.

No commits or functional changes exist between `image-release-0.5.9`
(`67dc72204f8dd738f0eac6b7dc149e1921f19a6f`) and the default branch used here.
Version alignment with Apassy 0.5.13; no protocol or schema change.
Team schema 6 and directory schema 1003 remain unchanged. The pinned core stays
at `73f3399`. Both CLI and relay inherit the root package version; OCI labels
are generated by Image CI. The Worker package and lock metadata also align.

Use the current runbook in [OPERATIONS](../OPERATIONS.md#current-release-runbook-github-artifacts-only),
including its artifact staging Python block, digest-chain checks, public gate,
and backup documentation. Historical deployment approvals do not apply here.
Require green PR CI including dependency advisories and owner publication approval.
Do not claim a coordinated release until all six surfaces are verified live.

## A. Build on GitHub only

After merge, record the approved full merge SHA as `RELEASE_SHA` (not the PR head).
On the release operator's isolated checkout:

```sh
RELEASE_SHA=<approved-full-merge-SHA>
git fetch origin
git switch --detach "$RELEASE_SHA"
git tag image-release-0.5.13 "$RELEASE_SHA"
git push origin refs/tags/image-release-0.5.13
gh run list -R wydrox/apassy-relay --workflow image.yml --commit "$RELEASE_SHA"
RUN_ID=<successful-Image-run-ID>
mkdir -p /tmp/relay-release/image /tmp/relay-release/linux /tmp/relay-release/darwin
gh run download "$RUN_ID" -R wydrox/apassy-relay -n relay-image -D /tmp/relay-release/image
gh run download "$RUN_ID" -R wydrox/apassy-relay -n apassy-team-linux-x86_64 -D /tmp/relay-release/linux
gh run download "$RUN_ID" -R wydrox/apassy-relay -n apassy-team-darwin-arm64 -D /tmp/relay-release/darwin
(cd /tmp/relay-release/image && shasum -a 256 -c relay-image.tar.gz.sha256)
(cd /tmp/relay-release/linux && shasum -a 256 -c SHA256SUMS-linux)
(cd /tmp/relay-release/darwin && shasum -a 256 -c SHA256SUMS-darwin)
```

`.github/workflows/image.yml` is triggered by `image-*` tags. It publishes Actions
artifacts, not a registry image. Tags inside the archive are
`apassy-relay:release-0.5.13` and `apassy-relay:sha-<full-source-SHA>`.
Require all three jobs from the same successful run. Record run URL, source SHA,
checksums and metadata before the seven-day artifact retention expires.
Verify release JSON version/commit, CLI filenames/hashes, amd64 image architecture,
OCI version/revision labels and config digest against inspect/id metadata.
On containerd stores, use the archive manifest-to-config digest chain specified
in OPERATIONS rather than comparing different digest types.

## B. Relay deployment and rollback (approved operator only)

No builds or tests run on production. The isolated restore drill below runs an
already built candidate, as required by the runbook. Before restarting, complete
the Worker/public gate in C. Preserve all existing settings, secrets and mounts.
On the approved VPS, with the verified archive transferred to
`/tmp/relay-release/image/`, run:

```sh
cd /opt/apassy
RELEASE_SHA=<approved-full-merge-SHA>
df -h .
docker compose config --images
docker inspect apassy-relay --format '{{.Image}}'
cp -p compose.yaml compose.yaml.pre-release-0.5.13
(cd /tmp/relay-release/image && sha256sum -c relay-image.tar.gz.sha256)
docker load -i /tmp/relay-release/image/relay-image.tar.gz
docker image inspect "apassy-relay:sha-$RELEASE_SHA"
# Verify loaded identity/labels against CI, including containerd digest chain.
docker compose exec -T relay apassy-relay admin backup
# Record the returned backup directory and verify its MANIFEST.
# Use the installed lock/manifest-checking wrapper for the operational backup:
sudo /opt/apassy/backup/apassy-relay-backup.sh
sudo env APASSY_RELAY_RESTORE_IMAGE="apassy-relay:sha-$RELEASE_SHA" /opt/apassy/backup/apassy-relay-restore-test.sh
```

The wrapper takes another consistent backup and validates its manifest; the
restore script chooses the latest dated backup and performs snapshot-check.
Archive the previous image and compose settings; keep the master-key backup
separate. Stop on any backup/restore/identity failure. Inspect the installed
backup tooling against the reviewed repository scripts before using it.

Swap only the relay image in the existing production compose file:

```sh
python3 - "$RELEASE_SHA" <<'PY'
import pathlib, re, sys
p = pathlib.Path('compose.yaml')
s = p.read_text()
s, n = re.subn(r'(?m)^(\s*image:\s*)apassy-relay:[^\s#]+',
               lambda m: m[1] + 'apassy-relay:sha-' + sys.argv[1], s)
assert n == 1, 'expected exactly one relay image; inspect manually'
p.write_text(s)
PY
docker compose config --images
docker compose up -d --no-deps --wait relay
docker compose exec -T relay apassy-relay admin readiness
systemctl list-timers apassy-relay-backup.timer apassy-relay-restore-test.timer
curl --fail --silent --show-error -D /tmp/relay-health.headers https://apassy-relay.wyderka.cc/healthz -o /tmp/relay-health.body
cat /tmp/relay-health.headers
printf 'ok\n' | cmp - /tmp/relay-health.body
```

Require HTTP 200, `x-apassy-relay-version: 0.5.13`, and
`x-apassy-relay-commit` equal to the approved full SHA. Verify authenticated
operator/Connect/approval/sync paths, original teams, backup timers, and health/logs
for ten minutes per the prior release checklist. Public liveness alone is insufficient.
Keep the sweep timer disabled/uninstalled unless separately approved.

For rollback, use the archived previous schema-6 image and compose settings:

```sh
cd /opt/apassy
docker compose stop relay
cp -p compose.yaml.pre-release-0.5.13 compose.yaml
docker compose up -d --no-deps --wait relay
```

Disable any new sweep timer before rollback. Recheck the previous version/commit,
readiness, authenticated paths and backups. No schema downgrade or DB restore is
needed; restarts interrupt runs. Full backup restoration is separate data recovery
and requires reconciliation of access changes. Preserve audit archives.

## C. Linux CLI and Worker `/dl/` publication

The same Image workflow's `linux-cli` job builds `--locked --bin apassy-team` on
GitHub ubuntu-24.04 in pinned Rust 1.97 Bullseye, checks `--version`, and rejects
GLIBC requirements above 2.31. No other build service is needed. Never extract
the downloadable CLI from the Trixie relay image or build it on production.
The `darwin-cli` job supplies the matching Apple silicon CLI.

At the approved artifact SHA, execute the exact Python staging block in
OPERATIONS, with `/tmp/relay-release/linux` and `/tmp/relay-release/darwin`.
It verifies both metadata source versions/commits and hashes, copies both binaries
to `deploy/worker/public/dl/`, and writes combined `SHA256SUMS` and `release.json`.
These generated files are intentionally ignored. Do not omit Darwin.

Before deployment run the public gate against the *current* release's matching
verified artifacts as a connectivity check. Then stage the candidate and run:

```sh
cd deploy/worker
npm ci --no-audit --no-fund
npm test
npm run typecheck
npm run preflight
# Only with separate owner deployment approval and verified account/bindings/secrets:
npm run deploy
cd ../..
python3 deploy/worker/scripts/check-public-assets.py --version 0.5.13 --commit "$RELEASE_SHA" --evidence-dir /tmp/relay-public-0.5.13-attempt-1
```

Record the Worker deployment ID and previous verified Worker ID. Do not bypass
Wrangler's build preflight. The public gate requires exact HTTP-200 bytes for
both binaries, SHA256SUMS, release.json, installer and guide; redirects,
challenges and exhausted retries stop the relay rollout. For Worker rollback,
from deploy/worker run `npx wrangler rollback <recorded-previous-Worker-ID> --yes`,
then verify all six assets against that previous release's matching artifacts.
Never reuse the historical 0.5.9 rollback ID without verifying what is current.

## D. Public version readback

The health command in B verifies the running relay version and full source SHA.
On a compatible Linux x86_64 machine, use a fresh empty evidence directory:

```sh
mkdir /tmp/apassy-public-0.5.13
cd /tmp/apassy-public-0.5.13
curl --fail --silent --show-error https://apassy-relay.wyderka.cc/dl/apassy-team-linux-x86_64 -o apassy-team-linux-x86_64
curl --fail --silent --show-error https://apassy-relay.wyderka.cc/dl/SHA256SUMS -o SHA256SUMS
curl --fail --silent --show-error https://apassy-relay.wyderka.cc/dl/release.json -o release.json
grep '  apassy-team-linux-x86_64$' SHA256SUMS > SHA256SUMS-linux
sha256sum -c SHA256SUMS-linux
# Compare hash and release.json to the independently verified CI artifacts too.
chmod 755 apassy-team-linux-x86_64
test "$(./apassy-team-linux-x86_64 --version)" = 'apassy-team 0.5.13'
```

A Mac cannot execute this Linux binary natively. Perform this readback on an
approved compatible non-production Linux host; CI's --version check alone is
not public download verification. No credentials are needed for these public GETs.
