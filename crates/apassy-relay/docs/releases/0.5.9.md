# Relay 0.5.9 release

The owner approved this production deployment on 2026-11-01: "Deploy 0.5.9 now".
This release includes PR #8 (merge `6ee3f58`): additive lost-reply Connect
recovery (F06), bounded/fair push retries and restart replay, including Worker
APNs deadlines (F07), private database readiness (F08), and a dry-run idle-team
sweep with optional timer units (F09). PR #10 (merge `719e93b`) adds per-team
CLI host services (F13), the JSON output contract (F15), and checked installs
(F16). APNs acceptance does not prove device receipt.

The relay, Worker, and both downloadable CLIs use `0.5.9`. The pinned `apassy`
dependency remains `73f3399`. Team schema 6 and directory schema 1003 are
unchanged; this release adds no database migration. Other application surfaces
require their own publication verification.

## Deployment gates

Follow the current GitHub-artifacts-only runbook in `../OPERATIONS.md`. Merge
this bump with a merge commit only after green CI, including dependency
advisories. Tag that exact merge SHA `image-release-0.5.9`; obtain the image and
both CLIs from the same successful Image run. Verify archive and CLI checksums,
metadata, architecture, OCI labels, and the config/manifest digest chain.
Build only on GitHub, never on the production VPS or in a local Docker VM.

Keep image `apassy-relay:release-0.5.8` and save the current compose file as
`/opt/apassy/compose.yaml.pre-release-0.5.9`. Take a fresh consistent backup,
verify its MANIFEST, and run the isolated restore drill using the verified
candidate immutable image and `snapshot-check` before restarting production.
Preserve previous backup tooling and install changed tooling through the
documented procedure. Leave the F09 sweep timer uninstalled or disabled: it
must remain dry-run until the owner reviews retention and audit archives.

Stage both verified downloads, combined SHA256SUMS, and release.json while
detached at the artifact merge SHA. Pass Worker tests, typecheck, and preflight;
check the existing public assets before deployment. Deploy the Worker, then
require all six public asset checks to pass before the relay restart. Select
the verified release image without changing service settings. Require HTTP 200
`ok\n` with version `0.5.9` and the exact merge SHA, Connect and operator smoke
tests, deletion of both synthetic teams, unchanged/open original teams, active
backup timers, private readiness for every team DB, and a ten-minute health/log
watch without panics, repeated errors, or a push retry storm. Do not use the
historical schema-5-to-6 `rollback-check` as a same-schema release gate.

## Owner's Mac CLI migration (separate owner action)

This deployment must not upgrade the owner's CLI, change its services, or
write `~/.config/apassy-team`. Before the owner upgrades, privately back up
that directory and any legacy `com.wydrox.apassy.team-host.plist`. Identify
the old service's explicit `--team` and saved relay/device identity; do not
infer ownership from the display name or an item UID alone.

For each legacy host-key entry, verify its relay URL, item UID and item ID
against the authenticated inventory of the intended stable team ID. In a
private editor, bind only verified entries to that exact `team_id`, preserving
the key material, other metadata, file mode 0600, and directory mode 0700.
Unbound keys deliberately cannot release credentials in 0.5.9. Resolve
ambiguous entries before starting a new host; never bulk-assign them by name.

After this check, the owner can install the verified 0.5.9 CLI at a stable path.
If a legacy service has an unambiguous `--team`, `apassy-team --team TEAM_ID
host install` migrates it while retaining its original team/options. If it
lacks a pinned team, preserve its plist, stop it with `launchctl bootout
"gui/$(id -u)/com.wydrox.apassy.team-host"`, and move the legacy plist outside
LaunchAgents before installing per-team hosts. Stop any foreground legacy host
as well. For each intended team, run `apassy-team --team TEAM_ID me`, then
`apassy-team --team TEAM_ID host install --ask-all --auto-limit 0` and
`apassy-team --team TEAM_ID host status`. Keep the desktop session open and
verify the team-pinned plist `com.wydrox.apassy.team-host.TEAM_ID.plist` and its
logs. Preserve stricter existing approval settings.

## Rollback

Stop at the first real failed check. Restore relay 0.5.8 with:

```sh
ssh ottervibe 'cd /opt/apassy && docker compose stop relay && cp -p compose.yaml.pre-release-0.5.9 compose.yaml && docker compose up -d --no-deps --wait relay'
```

From `deploy/worker`, restore the matching Worker and downloads with:

```sh
npx wrangler rollback 214b222c-0f1d-41fa-b309-7a1c9d275275 --yes
```

Restore any changed backup scripts/units from the preserved copies. Keep the
sweep timer disabled/uninstalled. Verify HTTP 200 and the 0.5.8 source headers,
all six 0.5.8 assets, original teams, and backup timers. No schema downgrade or
database restore is required. Keep all immutable audit archives; a full backup
restore is a separate data-recovery operation requiring access reconciliation.
